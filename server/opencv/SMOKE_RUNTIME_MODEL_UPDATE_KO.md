# 연기 런타임 및 적응 모델 변경 기록

## 목적

라즈베리파이 4채널 서버에서 NCNN 검출 결과가 생성돼도 freshness 만료로
Qt 박스가 누락되는 문제를 수정하고, 현장 세트장 연기에 추가 학습한 모델을
검증하기 위한 브랜치다.

## 런타임 변경

- 라즈베리파이 실측 추론 시간 약 1초/장을 기준으로 채널별 제출 주기를
  1초에서 4초로 조정했다. 단일 워커 전체 요구량은 약 1장/초다.
- 완료 시점의 `completedTime - sourceTime`이 2.5초를 넘는 결과는 버린다.
- 정상 완료 결과는 `completedAgeMs` 기준으로 5초간 유지한다.
- 채널별 갱신 주기가 약 4초이므로 연기 트랙은 첫 양성 결과부터 확정한다.
- 서버는 새 연기 결과 사이에 마지막 연기 박스를 캐시해 Qt로 전달한다.

## 모델 변경

- 입력: 640×384
- 클래스: `0=smoke`, `1=fire` (런타임은 smoke만 사용)
- NCNN blob: `in0`, `out0`
- 모델 폴더: `smoke_yolov8n_round2_full10_20260825_640x384_ncnn_model`

2차 현장 영상 적응 학습은 조기 종료를 끄고 10 epoch 전체를 수행했다.
최종 선택된 `best.pt`의 전체 검증 결과는 precision 0.7683, recall 0.6797,
mAP50 0.7587, mAP50-95 0.4458이다. smoke 클래스는 precision 0.775,
recall 0.703, mAP50 0.777, mAP50-95 0.484였다. 서버 입력과 맞추기 위해
NCNN은 반드시 640x384(`imgsz=(384, 640)`)로 다시 내보낸 파일을 사용한다.

일반 검증셋에서는 기존 대비 precision이 0.7603에서 0.7645로 소폭
상승했지만 recall은 0.7373에서 0.6975로 감소했다. smoke 클래스의
mAP50-95는 0.4643에서 0.4631로 거의 동일했다.

현장 목표 영상 189프레임(3프레임 간격 표본)에서는 confidence 0.25 이상
연기 검출 프레임이 2개에서 5개로 증가했고 최고 confidence는 0.2877에서
0.3740으로 증가했다. 따라서 전체 성능이 무조건 향상됐다고 표현하면 안 되며,
실제 카메라에서 연기·무연기·오탐 후보 조건별 반복 시험 후 main 반영 여부를
결정해야 한다.

## 병합 전 확인

1. 라즈베리파이에서 4채널을 동시에 실행한다.
2. 로그에서 채널별 결과 주기, `detectMs`, 파이프라인 지연을 확인한다.
3. 실제 연기 20회 이상과 무연기/회색 벽/작업복 등 오탐 조건을 분리 시험한다.
4. Qt에서 연기 박스가 결과 갱신 사이에도 유지되고 해제 후 사라지는지 확인한다.
