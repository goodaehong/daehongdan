# db — 센서 이력·사건 기록 (SQLite)

## 개요

서버가 남기는 기록을 담당한다. 1초마다 들어오는 센서값과, 경보처럼 불규칙하게 터지는
사건을 각각 다른 표에 넣고, Qt가 요청하면 조회해서 돌려준다.

---

## 동작

**표를 둘로 나눈 이유** — 조회 패턴이 정반대다.

| | `sensor_log` | `event_log` |
| --- | --- | --- |
| 성격 | 1초 주기 연속값 | 불규칙한 사건 |
| 조회 | 기간을 잘라 **구간 집계** | **사태 단위**로 묶어서 |

한 표에 넣으면 양쪽 조회가 다 나빠진다. 센서 이력에 사건을 섞으면 집계 때 걸러내야 하고,
사건 기록에 센서값을 섞으면 사태 하나를 보려고 수천 행을 훑어야 한다.

**집계는 DB에서 한다.** 하루치 센서 이력은 수만 행이라 원본을 그대로 Qt로 보내면 통신이
막힌다. 구간별 평균과 최댓값을 함께 보내 순간 스파이크가 평균에 묻히지 않게 했다.

**사태(incident) 단위로 다룬다.** 경고에서 위험으로 올라가고 해제될 때까지가 한 사태이고,
그 사이 기록은 `incident_id` 하나로 묶인다. 덕분에

- 해제 시 `resolveIncident()` 로 그 사태의 전 행을 한 번에 `해결됨` + 지속시간으로 바꾼다
- 오탐으로 판정되면 `markFalseAlarm()` 이 사태 전체를 일괄 변경한다
- 서버를 재시작해도 `maxIncidentId()` 로 번호를 이어받아 과거 사태와 안 섞인다

클립은 녹화가 13초 뒤에 끝나므로, 저장이 완료된 시점에 `updateClipPath()` 로 경로만
채워 넣는다.

## 주요 파일

| 파일 | 역할 |
| --- | --- |
| `Database.cpp/h` | 테이블 생성 · INSERT · 사태 처리 · 조회 SQL |
| `query_handler.cpp/h` | Qt의 `query` 요청 파싱 → 응답 조립 (`target`: `sensor_log` / `event_log`) |
| `factory.db` | SQLite 파일 — 실행 중 생성, 커밋 안 함 |
| `snapshots/` | 경보 시점 스냅샷 jpg — 실행 중 생성, 커밋 안 함 |
| `clips/` | 이벤트 클립 mp4 — 실행 중 생성, 커밋 안 함 |

## 참고

- 경로는 CMake가 주입한다 (`DB_PATH` · `SNAPSHOT_DIR` · `CLIP_DIR`) — 실행 위치와 무관하게 고정
- 이미 만들어진 DB에는 `CREATE TABLE IF NOT EXISTS` 가 새 컬럼을 안 붙여서,
  컬럼 추가는 `ALTER TABLE` 로 따로 처리한다
- 조회 요청·응답의 JSON 형식은 통신 명세서 참고
