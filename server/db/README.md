# db — 센서 이력 · 사건 기록 (SQLite)

## 📌 개요

- 1초 주기 센서값과 불규칙한 사건을 각각 다른 표에 저장
- 관제 화면 요청에 맞춰 조회·집계해서 응답
- 스냅샷 · 영상 클립 경로도 함께 관리

---

## ⚙️ 동작

### 표 구성

| | `sensor_log` | `event_log` |
| --- | --- | --- |
| 성격 | 1초 주기 연속값 | 불규칙한 사건 |
| 조회 방식 | 기간을 잘라 **구간 집계** | **사태 단위**로 묶어서 |
| 하루 행 수 | 수만 | 사건당 2~3 |

- 조회 패턴이 정반대라 한 표에 넣으면 양쪽 다 느려짐
- 센서 이력에 사건 혼재 → 집계 시 걸러내야 함
- 사건 기록에 센서값 혼재 → 사태 하나 보려고 수천 행 스캔

### 집계는 DB 에서

- 하루치 원본은 수만 행 — 그대로 보내면 통신이 막힘
- 구간별 **평균과 최댓값을 함께** 전송 → 순간 스파이크가 평균에 묻히지 않음

### 사태(incident) 단위 관리

| 시점 | 처리 |
| --- | --- |
| 경고 진입 | 사태 번호 발급 |
| 위험 승격 | 같은 번호 유지 |
| 해제 | 그 사태의 전 행을 「해결됨」 + 지속시간으로 **일괄 변경** |
| 오탐 판정 | 사태 전체를 일괄 변경 |
| 서버 재시작 | 최대 번호를 이어받아 과거 사태와 안 섞임 |

- 클립은 녹화가 13초 뒤에 끝나므로, 저장 완료 시점에 경로만 채워 넣음

## 📁 주요 파일

| 파일 | 하는 일 |
| --- | --- |
| `Database.cpp/h` | 표 생성 · 기록 저장 · 사태 처리 · 조회 |
| `query_handler.cpp/h` | 관제 화면 조회 요청 해석 · 응답 조립 |
| `factory.db` | SQLite 파일 — 실행 중 생성, 커밋 안 함 |
| `snapshots/` | 경보 시점 스냅샷 jpg — 커밋 안 함 |
| `clips/` | 이벤트 영상 클립 mp4 — 커밋 안 함 |
