# server — 라즈베리파이 메인 서버

## 📌 개요

- 카메라 4채널과 센서 4종을 받아 위험 여부 판정
- 원인에 맞는 대응을 자동 실행 — 밸브 · 환기팬 · 사이렌 · 전광판 · 음성
- 모든 사건을 기록하고 관제 화면으로 전송

---

## ⚙️ 동작

### 무슨 일이 일어나는가

```
① 입력      카메라 4채널 영상 · 센서 4종 값
                    ▼
② 판정      영상 감지와 센서를 교차 확인 → 안전 / 경고 / 위험
                    ▼
③ 대응      원인에 맞는 조치 실행 (화재냐 가스냐에 따라 다름)
                    ▼
④ 기록·전송  DB 저장 · 스냅샷 · 영상 클립 · 관제 화면 · 전광판
```

### 단계별로 하는 일

**① 입력**

- 영상 — MediaMTX 가 재배포하는 RTSP 를 채널별로 수신
- 센서 — 커널 드라이버가 노출한 값을 읽어 물리 단위로 환산
- 둘 다 실패할 수 있으므로 각각 별도 스레드에서 수집

**② 판정**

| 신호 | 위험 기준 |
| --- | --- |
| 가스 (MQ-9) | 200 ppm 경고 · 2000 ppm 위험 |
| 연기 (MQ-2) | 150 ppm |
| 불꽃 (DFR0076) | 1.0 V |
| 영상 — 화재 | **OpenCV 룰 기반** — 색 · 밝기 · 움직임 · 형태 조합, 연속 프레임 확정 |
| 영상 — 연기 | **NCNN YOLOv8n** — 모델 검출 + 대형 박스 움직임 확인, 최초 양성 1회 확정 |

- 영상 단독은 **경고**까지만 — 피부·노란 물체를 화염으로 오인할 수 있음
- 센서와 교차 확인돼야 **위험**으로 승격
- 위험 7조합 · 경고 3조합

**③ 대응**

| 원인 | 환기팬 | 밸브 | 사이렌 | 전광판 |
| --- | --- | --- | --- | --- |
| 화재 계열 | **차단** (산소 차단) | 차단 | ON | 화재 대피 화면 |
| 가스 계열 | **최대** (희석·배기) | 차단 | ON | 가스 대피 화면 |
| 해제 | 약 | 개방 | OFF | 평상 화면 |

**계열 구분**

| 계열 | 해당 조합 |
| --- | --- |
| 화재 | 화재영상+불꽃센서 · 연기영상+연기센서 · 연기센서 단독<br>가스+화재영상+불꽃센서 · 가스+연기영상+연기센서 · 가스+연기센서 |
| 가스 | 가스 단독 |

- 같은 환기팬이 원인에 따라 정반대로 동작
- 대피 화면 전환과 동시에 대피경로 전송
- 대피 안내 음성 재생

**④ 기록·전송**

| 시점 | 남기는 것 |
| --- | --- |
| 경고 진입 | 관제 화면 알림 · 카운트다운 · DB 기록 · 스냅샷 · 영상 클립 |
| 위험 진입 | 위 전부 + 대응 내역 · 전광판 전송 |
| 해제 | 사태 종료 처리 · 지속시간 확정 |
| 매초 | 센서 이력 · 관제 화면 갱신 |

- 경고 → 위험 → 해제가 **하나의 사태**로 묶여 조회됨
- 관리자가 경고를 확인하지 않으면 위험으로 자동 승격

### 경보 4단계

```
안전 ──▶ 경고     알림 · 기록만        영상 단독으로도 진입, 공정은 안 멈춤
     ──▶ 위험     자동 대응 실행       센서 교차 확인 후
     ──▶ 비상     관리자 수동 전환     체크리스트를 다 만족해야 해제
```

### 스레드 구성

```
sensorWorker   ×1    센서 입력만
cameraWorker   ×4    영상 입력 + 감지 요청
controlLoop    ×1    판정 · 대응 · 기록 · 전송         ← 결정은 여기 한 곳
QtRecvWorker   ×1    관제 화면 요청 수신
```

- 입력은 느리고 실패할 수 있어 각자 스레드에서 수집
- 판정부터 대응까지는 한 스레드에서 순서대로 — 순서가 뒤집히면 밸브가 열린 채 위험 상태가 됨
- 온습도 센서 하나가 최대 1초를 붙잡을 수 있어 입력을 분리

## 🔧 빌드·실행

**필요** — OpenCV 4.5+ · SQLite3 · NCNN · `libssl-dev`(TLS 사용 시) · `alsa-utils`

```bash
cmake -S server -B server/build
cmake --build server/build -j4
```

```bash
cd server && stdbuf -oL ./build/server_main
```

> ⚠️ MediaMTX 를 먼저 띄워야 합니다. 안 그러면 카메라 연결이 실패합니다
> → [streaming/](streaming/)

> ⚠️ `stdbuf -oL` 없이 출력을 파일이나 파이프로 넘기면 성공 로그가 버퍼에 갇혀 안 보입니다.
> 실패 로그만 나와서 마치 전부 실패한 것처럼 보입니다.

### 빌드 옵션

하드웨어가 없어도 개발·시연할 수 있도록 mock 으로 바꿀 수 있습니다.

| 옵션 | 기본값 | 용도 |
| --- | --- | --- |
| `USE_MOCK_SENSOR` | OFF | 센서 없이 |
| `USE_MOCK_ACTUATOR` | OFF | 액추에이터 보드 없이 |
| `USE_MOCK_DISPLAY` | OFF | 전광판 없이 |
| `ENABLE_TLS` | OFF | 관제 화면 연결에 TLS 사용 |
| `ENABLE_SMOKE_NCNN` | ON | 연기 감지 사용 |

현장마다 달라지는 값도 빌드 시 지정합니다.

| 옵션 | 기본값 |
| --- | --- |
| `QT_LINK_PORT` | `9999` |
| `RTSP_BASE_URL` | `rtsp://localhost:8554/cam` |
| `ACTUATOR_DEVICE` | `/dev/stm_actuator` |
| `STM_DISPLAY_DEVICE` | `/dev/stm_display` |
| `SPEAKER_ALSA_DEVICE` | `hw:2,0` |

## 🛠 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 카메라 연결 실패 | MediaMTX가 먼저 실행됐는지와 `RTSP_BASE_URL` 확인 |
| 연기 모델 로드 실패 | `ENABLE_SMOKE_NCNN`, NCNN 설치 경로, `detection/models/` 복사 여부 확인 |
| 감지는 되지만 공장 좌표가 없음 | 채널별 ArUco 설정과 `homography_ch*.yml` 생성 여부 확인 |
| ROI가 재시작 후 사라짐 | `ROI_CONFIG_PATH`와 `roi/roi_config.json` 쓰기 권한 확인 |
| Qt가 연결되지 않음 | 서버·Qt의 TLS 사용 여부와 포트가 서로 같은지 확인 |

로그를 파일로 받을 때는 `stdbuf -oL`을 사용해야 성공 로그도 즉시 기록됩니다.
