# detection — 화재 · 연기 · 사람 감지

## 📌 개요

- 카메라 프레임에서 화재 · 연기 · 사람을 검출하고, 화재 위치는 공장 좌표로 변환해 돌려줌
- 화재는 **OpenCV 룰 기반**, 연기는 **NCNN YOLOv8n**, 사람은 카메라 WiseAI 메타데이터
- 서버 본체와 분리되어 단독으로도 실행 가능

---

## ⚙️ 동작

```
프레임 제출 ──▶ [워커 스레드] 검출 ──▶ 결과 조회 ──▶ 박스 + 격자 좌표
```

### 감지 방식

| 대상 | 방식 | 확정 조건 |
| --- | --- | --- |
| 🔥 화재 | OpenCV 룰 — 색 · 밝기 · 움직임 · 형태 | 연속 프레임 누적 |
| 💨 연기 | NCNN YOLOv8n 모델 | confidence 0.40 이상 · 최초 양성 1회 확정 · 최대 5초 유지 |
| 🧍 사람 | 카메라 WiseAI 메타데이터 수신 | 카메라가 판정 |

- 화염은 색·밝기·움직임·형태로 구분 가능 → 룰로 처리
- 연기는 회색 벽 · 수증기와 겹쳐 룰로 안 잡힘 → 학습 모델 사용

### 처리 규격

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 수신 해상도 | 720p | MediaMTX 재배포 프로파일 |
| 분석 해상도 | 640×360 | 720p 그대로는 파이가 4채널을 못 버팀 |
| 연기 입력 | 416×256 | 모델 규격에 맞춰 원본 비율을 유지한 letterbox · stride 32 배수 |
| 워커 | **1개가 4채널 순차 처리** | 채널마다 스레드를 두면 CPU 포화 |
| 운영 confidence | 0.40 | 현장 검증 기준 |
| 확정·유지 | 최초 양성 1회 · 최대 5초 유지 | 공유 워커 처리 사이에도 박스 유지 |
| 모델 | Round 8, class 0=smoke | 메타데이터의 class 1=fire는 연기 런타임에서 사용 안 함 |

- 각 채널은 1초마다 최신 프레임을 제출하며, 처리 사이에는 확정된 직전 박스를 최대 5초 유지

### 좌표 변환

```
화염 박스 ──▶ 바닥 접촉점 ──▶ ArUco 변환식 ──▶ 60×60 공장 좌표
```

- 바닥 접촉점을 쓰는 이유 — 불의 실제 위치는 박스 중심이 아니라 바닥에 닿는 지점
- 전광판과 대피경로가 같은 좌표계를 공유
- 연기와 사람 박스는 화면 좌표로 전송하며 대피경로 장애물 좌표로 사용하지 않음

### 감지 제외 영역

- 원본 영상이나 모델 입력을 가리지 않음
- 검출 · 움직임 검증을 마친 **박스와 지정 영역의 겹침 비율**로만 판단 (기준 0.5)
- 활성 영역이 없으면 모든 검출을 그대로 통과
- 화재 / 연기에 따로 적용 가능 → [server/roi/](../roi/)

## 🛠 해결한 문제

### 1. 붉은색·주황색 물체를 화재로 감지하던 문제

초기 화재 감지는 화염색만 사용해 주황색 물체와 붉은 계열 물체도 불로 판단했다.
색상 마스크에 MOG2와 프레임 차분 기반 움직임 마스크를 결합해 정적인 색상 물체를
후보에서 분리했다.

움직임을 추가한 뒤에는 사람의 손과 피부가 화재 후보로 남았다. 이를 해결하기 위해
YCrCb·HSV 피부색 영역을 계산해 후보의 피부 겹침 비율을 점수에 반영했다.
마지막으로 색상·밝기·흰색 중심부·형태·움직임·질감·피부 겹침을 하나의 점수로
종합하고, 같은 위치에서 기준을 통과한 후보가 5회 누적될 때만 화재 박스를 확정한다.

```text
색상만 사용
→ 색상 물체 오탐
→ 움직임 추가
→ 피부 오탐
→ 피부 필터 추가
→ 복수 특징 점수제
→ 동일 위치 5 hit 확정
```

### 2. 현장 연기를 놓치고 무연기 채널을 감지하던 문제

기존 D-Fire 기반 모델은 세트장의 실제 연기를 놓치거나 회색 구조물과 무연기 채널을
연기로 판단했다. 학습 영상을 다시 확인한 결과, 채널 크롭 좌표와 전체 화면 좌표가
어긋난 라벨과 연기 주변 구조물까지 포함한 양성 박스가 원인 중 하나였다.

- 양성 박스를 실제로 보이는 연기 기둥만 감싸도록 다시 작성
- 연기 발생 전 구간과 무연기 채널을 hard negative로 추가
- 학습 전 라벨 검수 이미지를 생성해 박스 위치 확인
- 영상 단위 holdout을 유지해 같은 영상의 인접 프레임 누출 방지
- YOLOv8n Round 8을 NCNN으로 변환하고 PT·NCNN 결과를 비교
- 현장 운용값을 `confidence 0.40`, `1 hit`로 확정

Round 8 검증 결과는 precision 0.7563, recall 0.6715, mAP50 0.7035이다.
별도 현장 영상의 실제 연기 프레임 검출률은 84.8~93.3%였고, 해당 검증 영상의
무연기 채널에서는 오탐이 발생하지 않았다.
자세한 모델·배포 설명은
[docs/README_SMOKE_NCNN.md](docs/README_SMOKE_NCNN.md)를 참고한다.

### 3. 4채널 처리에서 과거 프레임이 밀리던 문제

모든 입력 프레임을 순서대로 쌓으면 추론 속도보다 입력 속도가 빠를 때 몇 초 전
프레임을 뒤늦게 처리하게 된다. 화재·연기 감지는 과거 프레임의 처리량보다 현재
상태를 빠르게 반영하는 것이 중요하므로 다음과 같이 변경했다.

| 적용 내용 | 해결 방식 |
| --- | --- |
| 최신 프레임 우선 | 채널별 pending frame을 가장 최근 프레임으로 덮어씀 |
| 화재 분석 주기 제한 | 640×360에서 채널당 167ms 간격(약 6FPS)으로 분석 |
| 연기 제출 주기 제한 | 채널당 1초마다 최신 프레임만 공유 Runtime에 제출 |
| 오래된 결과 폐기 | 처리가 끝났을 때 2.5초보다 오래된 입력 결과는 사용하지 않음 |
| CPU 스레드 제한 | OpenCV 내부 1 thread, ARM NCNN 2 threads |

연기 모델은 프로그램에서 한 번만 로드하고 하나의 worker가 네 채널을 round-robin으로
처리한다. 자세한 내부 최적화는
[docs/README_CPU_OPTIMIZATION.md](docs/README_CPU_OPTIMIZATION.md)를 참고한다.

### 4. 고정 조명·반사 영역에서 오탐이 반복되던 문제

특정 카메라의 고정 조명이나 반사 영역처럼 같은 위치에서 반복되는 오탐은 채널별
Ignore ROI로 해결했다. 원본 영상이나 모델 입력을 가리지 않고 전체 프레임에서 먼저
화재·연기를 검출한 뒤, 최종 박스와 다각형의 겹침 비율이 기준 이상인 결과만 제거한다.
따라서 ROI 경계에 실제 화재가 걸려도 감지에 필요한 색상·움직임 특징이 잘리지 않는다.

### 5. 수동 네 점 좌표 설정을 카메라마다 반복하던 문제

처음에는 카메라 화면에서 공장 영역의 네 모서리를 직접 지정해 영상 좌표와 공장
좌표를 연결하려 했다. 하지만 여러 카메라에서 같은 작업을 반복해야 하고, 바닥만
보이는 화면은 구분 가능한 자연 기준점이 부족해 동일한 실제 위치를 다시 선택하기
어려웠다.

ChArUco로 렌즈 왜곡을 먼저 보정하고, ID별 실제 공장 XY를 등록한 ArUco 마커로
대응점을 자동 생성한 뒤 RANSAC Homography를 계산하도록 변경했다. 검증된 행렬은
채널별 파일로 저장하므로 운영 중 마커를 매 프레임 검출하지 않는다. 화재 박스의
하단 중앙점을 공장 XY와 60×60 셀로 변환해 위험 통로를 제외한 대피 경로 재계산에
사용한다.

### 6. Raspberry Pi에서 사람 모델을 추가로 실행해야 하던 문제

사람 검출 모델을 Raspberry Pi에서 중복 실행하지 않고, 한화 WiseAI 카메라의 NPU가
생성한 ONVIF XML 메타데이터를 재사용했다. OpenCV가 읽지 못하는 data track은
FFmpeg receiver로 별도 추출하고, 오래된 메타데이터는 freshness 기준으로 폐기해
과거 사람 박스가 현재 화면에 남지 않도록 처리했다.
